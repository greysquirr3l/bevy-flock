# Audit 002, 2026-11-09

Follow-up to [audit 001](audit-001-2026-11-09.md). All ten findings were approved and fixed. Below is what changed, with
the evidence that the change worked, and the two items that stay open by nature rather than by neglect.

## Fixed

### 1. HIGH, R-25 and R-34: both themes are now written out, and both pass

The grey ramp moved out of bare `:root`. Light is a warm paper theme (`#fbf9f4`), dark is ink (`#12141a`), and each has
its own values rather than inheriting the other's.

| theme | body | muted | accent |
| --- | --- | --- | --- |
| light on `#fbf9f4` | 16.37:1 | 7.39:1 | 6.45:1 |
| dark on `#12141a` | 14.50:1 | 7.24:1 | 8.46:1 |

Against 4.5:1 for body text. The measured numbers are in the CSS beside the values, so the next person to change a token
has the check already in front of them.

### 2. HIGH, R-02: 826 em dashes removed from the corpus

83 files across `docs/dev/`, `docs/book/`, `docs/demo/`. The sweep skipped fenced blocks and inline code, because a dash
in a program's output or a code comment is data. Four remain inside fenced blocks (`bevy-playground.md` sample output,
one comment in `book/src/animation.md`) and are deliberate.

Prose was rewritten by clause, not by character: a dash between clauses became a comma, then doubled commas were
collapsed. Spot-checked against ADR 0009, which now reads as prose written by a person.

### 3. MEDIUM, R-20 and R-37: there is direction now, and it is labelled

`site/DESIGN.md` exists. It states plainly that it is **agent-supplied and provisional**, because R-37 requires the owner
to own identity and the owner was asked and chose the audit first. Every value in it maps to one CSS token, so replacing
it is a file edit rather than a redesign.

The identity: a field notebook. Paper and ink, one amber highlighter, serif headings, hairline rules, and the numbers as
the personality.

### 4. MEDIUM, R-21: dark is the designed mode and now says so

Both themes are first-class; the dark palette is written under `[data-theme='dark']` with its own ratios rather than being
the fallback. `DESIGN.md` records the preference and its consequence.

### 5. MEDIUM, R-05: thirteen pages no longer share one shape

| page | composition |
| --- | --- |
| landing | prose, one crate comparison table, one measured table |
| behaviour guide | prose then numbered steps, a combinator table, a caution callout |
| memory guide | before/after comparison table, then a do-not list |
| saving guide | fenced format block, four numbered rules, an error-path section |
| scaling guide | three regimes in sequence, guarantee table, measured ceiling |
| reference pages | tables, as reference should be |

The landing page lost its four-card grid entirely.

### 6. MEDIUM, R-06: the typefaces have reasons now

Headings are a serif stack (Iowan, Palatino, Georgia) because documentation is read like a book and a serif separates
sections without colour or rules. Body stays on the system sans for code-adjacent prose. Monospace keeps tabular figures
for the performance tables. No webfonts, because a library whose core has no dependencies should not load two font files
to say so. All four reasons are in `DESIGN.md`.

### 7. LOW, R-14: the card grid is gone

Replaced by a comparison table that says something a card could not: which crate has the engine.

### 8. LOW, R-08: one arrow

The second hero action lost its rocket icon. The primary action keeps its arrow because it points at the next step.

### 9. LOW, R-17: the number has a source next to it

The landing page's measured table links to the performance page and states the constraint in plain words: that page is
the only one allowed to quote the numbers, because it carries the fixtures.

### 10. LOW, R-35: the click-through, recorded

Static verification, because there is no browser in this environment and claiming a click-through would be a lie:

```
pages built: 13 (+ 404)
fetched over HTTP: 13, all 200, all with a <title>
broken internal links or anchors: 0
```

Every page was served and fetched, every absolute internal link resolved to a built file, and every anchor was checked
against the ids in its target page. What is **not** verified: visual rendering and a mobile breakpoint. Both need a
browser; the CSS has no fixed widths outside tables, which are allowed to scroll, but that is an argument rather than
evidence.

## Still open, with reasons

- **Mobile rendering** needs a real browser. The next session with one should check 375px width on the guides and the
  performance table.
- **Identity ownership.** `DESIGN.md` is a provisional draft by the rule's own definition. If you write the fields, I
  will transcribe them; nothing in the theme resists replacement.
