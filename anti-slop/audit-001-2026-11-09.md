# Audit 001, 2026-11-09

Scope: `site/` (13 pages, Astro + Starlight), `README.md`, and the docs that shipped with it (`docs/dev/`, `docs/book/`).
Mode: AFTER. Nothing below has been changed. Fix only the numbers you approve.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Findings

### 1. HIGH, R-25 and R-34: the light theme fails contrast, and it is my fault

`site/src/styles/custom.css` sets the grey ramp on bare `:root`, which both themes inherit. Measured against white:

| token | on `#ffffff` | required |
| --- | --- | --- |
| `--sl-color-gray-3` `#9a9db0` | **2.68:1** | 4.5:1 |
| `--sl-color-gray-2` `#c6c8d2` | **1.67:1** | 4.5:1 |

Dark mode passes comfortably (13.56, 11.31, 7.02). Light mode is therefore a shipped theme where body-adjacent text is
unreadable, which is R-34 by definition. Fix is to move the grey ramp into `:root[data-theme='dark']` and write a light
ramp in `:root[data-theme='light']`.

### 2. HIGH, R-02: 819 em dashes remain in the prose that predates today

`docs/dev/` 760, `docs/book/` 59. The README, the site and the 1.0 checklist are at zero after this morning's pass. These
are agent-written and are the same tell, but they are spread over 60 ADRs and a book rather than 15 files, so the fix is
a sweep with review, not a replace.

### 3. MEDIUM, R-20 and R-37: the site has no identity beyond a token swap

There is no `DESIGN.md`. The theme is four accent overrides on stock Starlight: swap the wordmark and the site could be
any project's docs. The logo mark (five dots converging) is the only owned element, and it appears once, in the sidebar.
This is a draft until you decide the identity; the theme file is small, so the cost of replacing it later is low.

### 4. MEDIUM, R-21: dark is the designed mode, light is the leftover

Every colour decision was made against `#101116`, and the light theme exists because Starlight ships one. That is fine as
a preference, but it should be stated, and finding 1 is the consequence of not stating it.

### 5. MEDIUM, R-05: every page has the same shape

Title, two or three paragraphs, a table, another paragraph. Thirteen times. It reads cleanly and it also reads like a
generated docs tree. The guides are the place to break the rhythm, since they have procedures in them.

### 6. MEDIUM, R-06: the typefaces are the default habit, not a decision

`--sl-font: Inter` is a no-op (Starlight already uses Inter) and `JetBrains Mono` is the reflex mono choice. Inter is
defensible for documentation; the problem is that no reason is recorded, which is the exact failure R-06 names.

### 7. LOW, R-14: the landing page is four identical cards

Four `Card` components, same size, same shape, same icon weight. They scan well, which is a purpose, so this passes at
LOW. If the landing page gets a real identity (finding 3), this grid should change with it.

### 8. LOW, R-08: both hero buttons carry an arrow

`icon: right-arrow` on Install and on A crowd in five lines. An arrow on a primary action is a signpost; on both, it is
decoration.

### 9. LOW, R-17: one number in the hero has no visible source

The tagline claims "Ten thousand agents in a frame". It is true and measured (10,000 at 16.6 ms is in the journals), but a
reader landing on the page cannot see where it comes from. Either link it to the performance page or soften it.

### 10. LOW, R-35: no click-through record

`pnpm build` succeeds and the output was inspected (14 pages, search index, `llm.txt`, zero broken internal links, the one
anchor link resolves). Nobody has clicked every nav item in a browser, and no mobile width has been checked. R-35 wants
that recorded, so it is recorded here as not done rather than claimed.
